## 2. プロジェクト紹介(6件)

各プロジェクトは「概要 → 担当・役割 → 技術スタック → 工夫点・学び → リンク」の順で統一フォーマットにする。

### (1) make-task-AI — 開発タスク詳細化システム(ベトナムインターン成果)

- 一言: 曖昧なユーザーストーリー・受け入れ条件を、複数のAIエージェント(PM/バックエンド/セキュリティ/QA/UX視点)が多角的にレビューし、具体的な開発タスクへ自動分解するシステム
- 期間: Techzen Company Limited(ベトナム・ダナン)でのインターン、約1か月
- 体制: 2名(自分はリーダー、要件定義・仕様設計・スケジュール管理・実装の大部分を担当)
- 技術スタック: Python, LangChain, LangGraph, OpenAI API, Pydantic, Docker, Git/GitHub
- 背景・課題: 多数の学生インターンが参加する環境で、技術力差による受け入れ条件(AC)の解釈のズレ・手戻りが発生していた
- 工夫点:
  - 単一AIでは出力精度が不安定だったため、「評価AIエージェント(複数専門家視点)→問題点分析AIエージェント→改善提案AIエージェント」の3段構成のレビューループをLangGraphで設計
  - hallucination対策としてPydanticで出力JSON構造を固定
  - ベトナム語のスライドを自作し、メンターへ直接提案。複数エンジニアを集めたミーティングを実現した
- 学び: 実装能力以上に「仕様を正しく構造化して共有する能力」がチーム開発全体に与える影響の大きさを実感。US/ACを「人間の要求を構造化する技術」として捉え直すきっかけになった
- リンク: https://github.com/KaichoHarry/make-task-AI

### (2) The-8-PM-Challenge(20時の挑戦状)

- 一言: AIが生成した「支離滅裂ななぞなぞ」を毎日20時に公開するWebゲーム。AIの弱点(なぞなぞが作れない)を逆手に取ったエンタメ企画
- 大会: 技育CAMP2025 Vol.12(努力賞受賞)
- 期間: 2025年8月28日〜9月5日(9日間、オンライン)
- 体制: 3名(はりぃ/S.Ka/K.Haruki)、自分はチームリーダー兼PM。企画立案・要件定義・仕様書/設計書作成・UI設計・API設計・進捗管理・統合作業・プレゼンを担当
- 技術スタック: React, TypeScript, Vite ほか(詳細設計はNotionドキュメント参照)
- 工夫点:
  - Notionに仕様書・設計書を先に整備し、メンバーがAIへ指示を出しながら実装を進められる土台を作った
  - フロントエンド/バックエンド間のJSON構造不一致によるバグを自ら両方のコードを確認して修正
  - 過去5問を参照して生成条件を変化させ、毎日異なる問題が出るよう設計
- 学び: 「完成させること」の重要性。AI時代は書ける力よりも「AIの特性・弱点をどう価値に変換するか」を考える力が重要だと実感
- リンク: https://github.com/H4aruki/The-8-PM-Challenge(チームメンバーH4aruki氏のリポジトリ。README・デモ・Contributors表記まで整っているためこちらを掲載)
- デモ: https://h4aruki.github.io/The-8-PM-Challenge/
- 設計書: https://hurricane-dance-850.notion.site/25f605b98b4f80c180afe5b8e7b3f352

### (3) AI-shiritori-app — AIしりとりアプリ

- 一言: ソロプレイ・AI対戦・文章しりとり(フリートーク)の3モードを備えたWebしりとりアプリ。ほぼ全工程をClaude Code(AI駆動開発)で実装
- 体制: 個人開発
- 技術スタック: フロントエンド Next.js(React)+ TypeScript + Tailwind CSS + shadcn/ui、バックエンド Go、DB PostgreSQL、AI Google Gemini API、Docker Compose、デプロイ Railway
- 工夫点:
  - AI対戦はGemini APIを使わず、IPADIC辞書(kagome形態素解析)から約23万語の索引を約25msで構築し、難易度別のランダム性で強さを調整
  - 文章しりとり(フリートーク)では文末の読み仮名を句読点・漢字を無視して抽出するロジックを実装
  - メール(SMTP/IMAP)を使った独自の管理者承認型パスワード再設定フローを設計・実装
  - 50アカウント作成・各モード50回プレイという大規模自動テストを実施し、バグをIssue化して修正
- 学び: AIを活用した開発における「要件を曖昧にせず都度確認しながら進める」重要性、および実際に手を動かして不具合を発見・修正するデバッグ力
- リンク: https://github.com/KaichoHarry/AI-shiritori-app

### (4) 顔面偉業診断(face-achievement-diag)

- 一言: 顔画像から、その人物が将来成し遂げる「偉業」(ノーベル賞受賞者、億万長者など)をAIが予測・診断するWebアプリ。「現状」ではなく「未来」にフォーカスした占い的AIコンテンツ
- 体制: 2名(自分はバックエンド/インフラ担当、フロントエンドは澁谷氏が担当)
- 技術スタック: バックエンド Python + PyTorch + FastAPI、DB PostgreSQL(大学サーバー)、フロントエンド HTML/CSS/JS、GitHub Pages、Docker
- 工夫点: 既存のAIが「現状分析」に寄りがちな中、あえて「未来予測」というエンタメ方向へ振り切ったコンセプト設計
- リンク: https://github.com/KaichoHarry/face-achievement-diag

### (5) TalkSeed(トークシード)

- 一言: 飲食店やイベント会場の待ち時間に、AIが会話参加者として加わり話題提案・深掘り質問・共感で会話を支援するアプリ(プッシュトゥトーク方式の音声対話)
- 体制: 4名チーム、プロトタイプ稼働中
- 技術スタック: フロントエンド React + Vite(TypeScript)、バックエンド Flask、音声認識 Whisper、音声合成 edge-tts、生成AI Google Gemini API、DB SQLite(本番はTurso)
- 工夫点:
  - 人物ごとの記憶(会話全文は保存せず、AIが生成した要約のみ保持)によりプライバシーへ配慮しつつパーソナライズを実現
  - シーン(場所・関係性・気分)に応じた話題提案ロジック
- 現状: リポジトリはPrivateのため、ポートフォリオ掲載にあたりPublicへ変更予定
- リンク: https://github.com/KaichoHarry/talk-seed (公開設定変更後に有効化)

### (6) MyTechPulse(近日公開)

- 一言: IT技術記事の情報過多による「学習疲れ」を解消するため、ユーザーのクリック履歴から興味関心を推定し、今の自分が理解できる範囲を起点に少しずつ新分野へ広げる技術記事パーソナライズサービス
- 大会: Open Hack U 2025 KANAZAWA
- 体制: 2名、自分はチームリーダー兼PM(企画・要件定義・UI設計・フロントエンド実装・API設計・プレゼンを担当)
- 技術スタック: フロントエンド HTML/CSS/JS、独自の指数的減衰(Exponential Decay)による興味推定アルゴリズム、DB設計(user/tag/recommendの3テーブル構成)
- 状態: 未デプロイのため、ポートフォリオには「近日公開」として概要のみ掲載し、デモ・リポジトリリンクは付けない
- 補足: 審査員から「短期間開発とは思えないほどUIが整理されている」と評価された一方、「大学生らしい尖った発想」の弱さが反省点
