# ポートフォリオサイト 仕様書(技術設計)

作成日: 2026-07-27
対象リポジトリ: https://github.com/KaichoHarry/portfolio (Next.js + TypeScript, 既存のcreate-next-app scaffold)

## 1. 目的・ターゲット

- 目的: 就職・転職活動における作品紹介。開発した6プロジェクトを一箇所にまとめ、採用担当者がコード・役割・技術スタックを確認できるようにする。
- 想定閲覧者: 日本企業の採用担当者(日本語)、海外/外資系企業の採用担当者(英語)、ベトナム語話者(Techzenインターン関係者など)。
- 更新頻度: 低頻度(新しい制作物を追加する都度、静的にコンテンツを追加する運用)。

## 2. 技術スタック

| 項目 | 選定 | 理由 |
|---|---|---|
| フレームワーク | Next.js (App Router) + TypeScript | 既存の `portfolio` リポジトリがcreate-next-appで作成済み。継続利用する |
| スタイリング | Tailwind CSS | 当初shadcn/uiの採用も検討したが、実装したページではTailwindの素実装のみで完結したため、未使用のscaffold(app/components/ui, app/components/figma)は削除した |
| コンテンツ管理 | ローカルJSON/TypeScriptオブジェクト(またはMDX) | プロジェクト数が6件程度と少なく、更新頻度も低いためDB不要。ビルド時に静的生成(SSG)する |
| データベース | 使用しない | 問い合わせフォームも含め、外部サービス(下記6章参照)で代替し、Postgres/Supabase等は導入しない |
| 多言語対応 | next-intl (または next-i18next) | App Routerとの親和性が高いnext-intlを推奨 |
| デプロイ | Vercel | Next.js標準のホスティング先。既存リポジトリのREADMEにも記載あり |
| アナリティクス | Vercel Analytics(任意) | 追加コストなく導入可能 |

## 3. 多言語対応方針

- 対応言語: 日本語(ja, デフォルト) / 英語(en) / ベトナム語(vi)
- URL構成: `/ja/...` `/en/...` `/vi/...` のパスプレフィックス方式(next-intlの標準構成)
- 未対応言語でアクセスした場合は `ja` にフォールバック
- 翻訳データ: `messages/ja.json` `messages/en.json` `messages/vi.json` に分離
- 優先度: まず日本語版を完成させ、英語版を次に用意する。ベトナム語版は工数次第で後回しにしてもよい(Techzenインターン関係者へ見せる用途が主なため、優先度は英語より下でも可)
- 注意: プロジェクト紹介文は日本語で書いた長文を機械的に3言語へ流用するのではなく、英語版は英語圏の採用担当者向けに要点を簡潔にまとめ直す(直訳すると冗長になりやすいため)

## 4. ページ構成・ルーティング

```
/[locale]/                  トップページ(ヒーロー、自己紹介要約、注目プロジェクト、CTA)
/[locale]/about             自己紹介詳細(経歴、スキル、課外活動)
/[locale]/projects          プロジェクト一覧(6件をカード表示)
/[locale]/projects/[slug]   プロジェクト詳細(担当・技術スタック・工夫点・リンク)
/[locale]/contact           連絡先(メール、X、GitHubへのリンク)
```

- プロジェクト詳細は動的ルート(`[slug]`)にし、`content/projects/*.ts` のようなデータファイルから生成する。今後プロジェクトが増えてもページ追加不要にする。
- トップページの「注目プロジェクト」は make-task-AI(ベトナムインターン成果)と AI-shiritori-app を優先表示(最も文章量・技術的深さがあるため)。

## 5. データ構造(例)

```ts
// content/projects.ts
type Project = {
  slug: string;
  title: string;
  period: string;
  role: string;          // 自分の役割
  teamSize: number;
  techStack: string[];
  summary: string;       // 一覧カード用の短い説明
  description: string;   // 詳細ページ用の長文
  links: {
    github?: string;
    demo?: string;
    docs?: string;       // 設計書などの外部リンク(Notion等)
  };
  status: "public" | "coming-soon"; // MyTechPulse用に coming-soon を用意
};
```

## 6. お問い合わせフォームについて

- DBを持たないため、フォーム送信はサーバーレスで完結する外部サービスを利用する。
  - 候補: Resend / Formspree / EmailJS のいずれか(APIキーをVercelの環境変数に設定するだけで完結)
- 最小構成であれば、フォームを置かず「メールアドレスをコピー」ボタン + mailtoリンクのみでも十分機能する。まずはこちらから始め、必要になったらフォームを追加する運用でよい。

## 7. SEO / OGP

- Next.jsの Metadata API で各ページに `title` / `description` を設定
- OGP画像は共通の1枚を用意(名前・肩書き・GitHubアイコンなど)。プロジェクトごとのOGP画像は任意
- `sitemap.xml` / `robots.txt` はNext.js標準機能で自動生成

## 8. レスポンシブ・アクセシビリティ

- モバイルファーストで実装(スマホでの閲覧を主想定)
- 画像には必ず `alt` を設定
- コントラスト比・フォントサイズはTailwindのデフォルトトークンに準拠
